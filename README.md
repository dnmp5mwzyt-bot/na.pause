# На паузе — сайт кофейни

Одностраничный сайт кофейни «На паузе» (Москва, Челябинская ул., 19 к4)
с панелью управления меню.

Фронтенд — статика без сборки: откройте `index.html` в браузере.
Панель и API работают только на Vercel (нужны serverless-функции).

## Структура

| Файл | Назначение |
| --- | --- |
| `index.html` | страница сайта |
| `styles.css` | стили, фирменная палитра |
| `script.js` | табы меню, мобильная навигация, подстановка меню из API |
| `admin.html` / `admin.css` / `admin.js` | панель управления меню |
| `api/menu.js` | `GET` — отдать меню, `PUT` — сохранить (нужен токен) |
| `api/login.js` | вход по паролю, выдаёт токен на 8 часов |
| `api/_lib.js` | хранилище, подпись токенов, проверка данных |
| `assets/` | логотип и фотографии |

## Панель управления меню

Адрес: `https://<ваш-домен>/admin`. Ссылки с сайта на неё нет —
страница закрыта от индексации и открывается только по прямому адресу.

Что умеет:

* менять название, описание и цену любой позиции;
* добавлять и удалять позиции, менять их порядок;
* помечать позицию как хит (жёлтый значок «хит» на сайте);
* временно скрывать позицию с сайта, не удаляя её;
* добавлять, переименовывать, удалять и переставлять разделы;
* менять подпись под заголовком меню;
* выгружать текущее меню в JSON.

Правки видны на сайте сразу после сохранения (ответ API кэшируется на 10 секунд).

### Настройка на Vercel

Пока не выполнены оба шага, панель открывается, но кнопка сохранения
возвращает ошибку — сайт при этом работает на встроенном меню.

**1. Хранилище.** В проекте на Vercel: **Storage → Create Database →
Upstash for Redis**, привязать к проекту. Интеграция сама добавит
переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN`.
Если подключаете Upstash напрямую, подойдут и `UPSTASH_REDIS_REST_URL`
с `UPSTASH_REDIS_REST_TOKEN` — код принимает оба варианта.

**2. Пароль.** **Settings → Environment Variables** → добавить
`ADMIN_PASSWORD` со своим паролем (Production и Preview).

После добавления переменных нужен **новый деплой** — Vercel подставляет
их только при сборке.

### Как это устроено

Меню хранится в Redis одним ключом `napauze:menu`. Пароль на сервер
целиком не попадает в хранилище: `/api/login` сверяет его с переменной
окружения и выдаёт подписанный HMAC-токен на 8 часов, которым
подписываются запросы на сохранение. Смена `ADMIN_PASSWORD` немедленно
делает все выданные токены недействительными. Подбор пароля ограничен:
8 неудачных попыток с одного IP — пауза на 15 минут.

Всё, что приходит из браузера, на сервере проверяется заново: длина
названий, диапазон цен, количество разделов и позиций. Ошибки
валидации возвращаются текстом и показываются в панели.

### Запасной вариант

Меню в `index.html` свёрстано статически, а `script.js` подменяет его
данными из API. Если JS выключен, API недоступен или хранилище не
подключено — посетитель видит статическую версию, а поисковики
индексируют её же.

Из-за этого статическая разметка со временем расходится с реальным
меню. Она не влияет на то, что видят посетители, но если хочется
держать её в актуальном виде — выгрузите JSON из панели и обновите
разметку в `index.html` и объект `DEFAULT_MENU` в `api/_lib.js`.
